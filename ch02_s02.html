1. 데이터파일시스템의 개념 및 종류

1) 자료의 계층구조

파일시스템은 자료의 계층구조를 가지고 있어 데이터를 효율적으로 저장하고 검색할 수 있다.

블록(Block)

  • 파일시스템의 가장 낮은 계층으로, 일정한 크기의 데이터 조각으로 파일시스템에 저장됨
  • 각 블록은 고유한 주소를 가지고 있으며, 파일시스템은 이러한 블록들을 조직화하여 파일이나 폴더에 할당함

파일(File)

  • 사용자가 생성하는 데이터의 단위
  • 블록들의 집합으로 구성되며, 각 파일은 파일시스템에서 고유한 식별자(파일명 혹은 파일 경로)를 가짐
  • 데이터와 파일에 대한 메타데이터(파일 크기, 생성 일자, 수정 일자 등)를 포함

디렉토리(Directory)

  • 파일이나 다른 디렉토리를 포함할 수 있는 컨테이너 역할. 파일을 조직화하기 위한 계층구조를 제공함
  • 각 디렉토리는 고유한 식별자인 디렉토리 경로를 가지며, 사용자는 디렉토리를 통해 파일에 쉽게 접근할 수 있음
컴퓨터 파일 구조를 생각하면 이해하기 쉽다. 하드디스크의 최소 저장 단위가 블록, 블록들을 묶어 내용을 담은 것이 파일(문서·이미지 등), 파일들을 폴더로 정리한 것이 디렉토리다.

2) 데이터파일시스템의 개념

데이터파일시스템 : 파일시스템과 데이터베이스관리시스템을 통칭함.

파일시스템

  • 파일과 폴더를 저장·관리·접근하는 체계로서, 자료의 계층구조를 통해 데이터를 구조화하고 조직화함
  • 데이터를 논리적으로 구성하고 저장 장치에 효율적으로 배치하여 파일의 생성·수정·삭제·검색 등의 작업을 수행
  • 일반적으로 하드디스크·SSD·네트워크 드라이브 등의 저장 장치에 적용됨
  • 파일·폴더·디렉토리를 통해 자료의 계층구조를 구현
  • 폴더에 대한 접근 권한도 관리하며, 읽기·쓰기·실행 등의 권한을 할당하여 데이터 보안 유지

데이터베이스관리시스템(DBMS, Database Management System)

  • 파일시스템의 단점을 극복하기 위해 등장한 개념
  • 데이터베이스에 접근하여 데이터베이스의 정의·조작·제어 등의 관리를 지원하는 소프트웨어
  • 데이터베이스(Database) : 서로 관련 있는 데이터의 집합. 중복된 데이터를 제거하고 데이터를 구조화함으로써 효율적인 처리 가능

3) 데이터파일시스템의 종류 및 특성

(1) 파일시스템의 종류 및 특성

파일시스템의 종류

  • 대표적인 파일시스템 : FAT32, NTFS, ext4, APFS, HFS+ 등
  • 각 운영체제와 저장 장치에 맞게 최적화되어 발전

파일시스템의 특징

특징내용
조직화된 데이터 저장파일의 크기에 맞게 데이터를 블록 단위로 나누어 저장하고, 각 파일에 대한 메타데이터를 관리함. 효율적인 관리와 검색 가능
계층구조파일과 폴더의 계층구조를 제공. 폴더는 파일을 그룹화하고 계층적으로 조직화하는 데 사용됨
파일 및 폴더의 식별자각 파일과 폴더를 고유한 식별자로 식별하여 파일에 접근할 수 있음
접근 권한 관리파일과 폴더에 대한 접근 권한을 관리함
백업과 복구데이터의 백업과 복구를 지원함

파일시스템의 단점

단점내용
데이터 중복 및 일관성 문제여러 파일에 동일한 데이터를 중복 저장하는 경우 데이터의 일관성이 깨질 수 있음
데이터 무결성 유지의 어려움잘못된 데이터 입력, 데이터 손상, 데이터 일관성 오류 등으로 데이터의 정확성이 보장되지 않을 수 있음
제한된 데이터 검색 및 쿼리 기능기본적인 검색 기능만 제공하고, 복잡한 데이터 검색 및 쿼리 작업에는 제한적 (쿼리(query) : 데이터베이스 등에서 원하는 정보를 검색하기 위해 요청하는 것)
확장성 문제데이터 양이 증가하거나 요구사항이 변경될 경우 처리에 제한적
동시성 및 병행 처리의 문제여러 사용자가 동시에 데이터에 액세스하거나 수정하는 것이 어려움

(2) 데이터베이스관리시스템의 종류 및 특징

DBMS의 기능

기능내용
데이터의 구조화테이블이나 컬렉션 구조를 사용하여 중복된 데이터를 최소화하고 데이터 일관성과 무결성 유지
데이터의 무결성 제약조건스키마를 정의하고 제약조건을 설정. 특정 속성이 고유한 값을 가져야 한다거나, 참조 관계에서 부모 테이블 레코드 삭제 시 자식 테이블 관련 레코드도 삭제되어야 하는 등의 제약조건 정의 가능
데이터의 동시 접근 제어트랜잭션 개념을 도입하여 여러 작업을 논리적으로 묶고, 트랜잭션 수준의 잠금 메커니즘으로 충돌 방지
데이터의 보안성사용자 인증과 권한 부여를 통해 접근 제어 관리, 데이터 암호화 지원, 로그 파일 활용
데이터의 공유와 일관성 유지트랜잭션이 ACID 원칙을 준수하도록 지원
  • 트랜잭션(Transaction) : 데이터베이스에서 처리의 기본단위. 갱신으로 인해 일시적으로 정합하지 않은 데이터가 사용되지 않도록 일련의 조작을 묶어서 처리함
  • ACID : 트랜잭션의 4가지 속성
    • 원자성(Atomicity) : 트랜잭션의 모든 연산이 완전히 수행되거나 전혀 수행되지 않아야 함
    • 일관성(Consistency) : 트랜잭션 실행 전과 후의 상태가 정의된 규칙과 제약조건을 준수
    • 고립성(Isolation) : 동시에 수행되는 트랜잭션들이 서로 영향을 미치지 않아야 함
    • 지속성(Durability) : 성공적으로 완료된 트랜잭션의 결과는 영구적으로 반영되어야 함
은행 계좌 이체를 예로 들면 — A계좌에서 출금과 B계좌로 입금이 하나의 트랜잭션이다. 출금은 됐는데 입금이 안 되면 안 되기 때문에, 둘 다 성공하거나(완료) 둘 다 취소(롤백)되어야 한다. 이것이 트랜잭션의 원자성이다.

DBMS에서의 데이터 종속성 관리

DBMS는 데이터 종속성을 적절히 관리해야 하며, 관리하지 않으면 아래와 같은 문제가 발생한다.

  • 데이터 종속성 : 데이터베이스에서 테이블 내 속성들 사이의 종속 관계를 나타내는 개념
  • 예 : '주민등록번호'가 제시되면 그 사람의 '이름'을 알 수 있음 → '이름'이라는 속성은 '주민등록번호'에 종속됨. 반대는 성립하지 않음

데이터 종속성 미관리 시 문제점

문제내용
데이터 중복과 일관성 문제같은 내용의 데이터가 다수의 테이블에 중복 저장 → 데이터베이스 용량 낭비 및 일관성 훼손
데이터 무결성 문제무결성 제약조건 위배 → 데이터의 정확성과 일관성 보장 불가
유지보수의 어려움복잡한 종속성 구조로 하나의 속성 수정 시 관련된 모든 종속 속성 수정 필요
성능 저하데이터 검색·조작·테이블 간 조인 작업 등이 더 복잡하고 느려질 수 있음
  • 무결성 : 데이터베이스 내의 데이터가 정확하고 일관된 상태를 유지하는 것

DBMS의 종류

종류내용
계층형(Hierarchical) DBMS트리(tree) 형태의 계층적·종속적인 관계로 구성한 DBMS
네트워크(Network) DBMS데이터 구조를 네트워크상의 노드 형태로 표현하여 각 노드를 대등한 관계로 구성한 DBMS
관계형(Relational) DBMS데이터를 테이블 형태로 구성하고, 테이블 간의 관계를 기반으로 데이터를 구성한 DBMS
  • 계층형 DBMS와 네트워크 DBMS는 현재는 거의 사용되지 않음

관계형 데이터베이스관리시스템(RDBMS, Relational Database Management System)

  • 관계형 데이터베이스를 생성·조작·관리하기 위한 소프트웨어 시스템
  • 주요 RDBMS : Oracle, MySQL, PostgreSQL, SQL Server 등

주요 특징 및 기능

기능내용
테이블 구조데이터를 테이블(행과 열)로 구성. 각 테이블은 속성(열)으로 구성되며, 데이터는 속성들의 값으로 표현
관계 정의테이블 간의 관계를 기본키와 외래키를 통해 정의하고 유지
데이터 일관성무결성과 일관성 유지를 위해 제약조건을 정의하고 적용
질의 언어(SQL)SQL(Structured Query Language)을 제공하여 데이터 검색·조작·조건부 검색 등을 수행
공유 및 동시성 제어다중 사용자 환경에서 데이터 공유와 동시성 제어 지원
데이터 보안사용자 권한과 접근 제어를 통해 데이터 보안 관리

2. 데이터베이스 이해

1) 데이터베이스 구성요소

테이블(Table)

  • 데이터베이스에서 정보를 구조화하여 저장하는 단위. 엔터티(Entity) 또는 릴레이션(Relation)이라고도 함
  • 행과 열로 구성된 2차원 구조로, 데이터의 집합을 나타냄
  • 각 테이블은 고유한 이름을 가지며, 특정 유형의 데이터를 저장하는 역할
  • 예 : "학생"이라는 테이블은 학생들의 정보를 저장하는 역할

속성(Attribute)

  • 테이블의 열을 나타내며, 특정 데이터 유형에 대한 정보를 기술. 필드(Field) 또는 변수(Variable)라고도 함
  • 각 속성은 고유한 이름을 가지며, 해당 속성에 저장되는 데이터의 유형을 정의
  • 예 : "이름", "나이", "성별"과 같은 속성은 "학생" 테이블에서 각 학생의 이름·나이·성별 데이터를 저장

레코드(Record)

  • 테이블의 행을 나타내며, 튜플(Tuple)이라고도 함
  • 각 레코드는 테이블의 속성에 해당하는 값들의 집합으로 구성
  • 예 : "학생" 테이블의 한 레코드는 특정 학생의 이름·나이·성별 등에 대한 값을 포함
테이블·속성·레코드의 관계 : 엑셀 스프레드시트로 이해하면 쉽다. 시트 전체가 테이블, 각 열(이름·나이·성별 등)이 속성, 각 행(학생 한 명의 데이터)이 레코드다.

메타데이터(Metadata)

  • 데이터에 대한 데이터. 데이터의 특성·구조·의미 등을 설명하는 정보
  • 주요 역할
    • 데이터의 의미와 구조 설명 : 테이블의 속성 이름·데이터 유형·제약조건·관계 등 포함
    • 데이터 검색·조회에 활용 : 테이블 이름·속성 이름·인덱스 정보 등 포함
    • 데이터의 일관성과 제약조건 유지 : 테이블 간의 관계·제약조건·외래키 등 정의
    • 데이터 분석 및 가공 지원 : 데이터 유형·형식·크기·통계 정보 등 포함
    • 데이터베이스 보안 관리 : 접근 권한·사용자 권한·보안 제약조건 정보 포함

데이터 딕셔너리(Data Dictionary)

  • 데이터베이스시스템에서 사용되는 데이터 구조와 메타데이터에 대한 정보를 저장하고 관리하는 역할
  • 데이터베이스 객체(테이블·속성·제약조건 등)의 정의·구조·속성·통계 등의 데이터에 대한 설명과 정보 포함
  • DBMS에서 중요한 역할을 하며, 데이터의 정확성과 일관성을 유지하는 데 도움

트랜잭션 관리자(Transaction Manager)

  • 데이터베이스에서 트랜잭션의 관리와 제어를 담당
  • 트랜잭션의 시작·종료·병합·롤백 등의 작업을 처리하여 데이터의 일관성과 동시성 제어를 관리

저장 데이터 관리자

  • 데이터베이스의 저장 구조와 데이터의 물리적인 저장·접근·관리를 담당
  • 블록 할당·파일시스템·인덱스 구조·버퍼 관리 등을 관리하여 데이터의 효율적인 저장과 검색 지원

질의 처리기(Query Processor)

  • 사용자의 질의(SQL)를 처리하고 데이터베이스로부터 원하는 정보를 추출하는 역할
  • 사용자가 요청한 질의를 해석하고, 최적의 실행 계획을 생성하여 데이터를 검색하거나 조작

2) 데이터베이스 구조

① 스키마(Schema)

데이터 구조와 제약조건을 명세하는 것으로, 개체·속성·관계의 정의와 그들이 유지해야 할 제약조건을 포함함. 데이터베이스관리의 관점에서 외부 단계, 개념 단계, 내부 단계로 구분되며, 이를 3단계 데이터베이스 구조라고 함.

스키마내용
외부 스키마사용자나 응용 프로그램의 관점에서 데이터베이스 정의. 특정 사용자 그룹이나 응용 프로그램에 필요한 데이터의 논리적 구조와 접근 방법을 정의. 각각의 외부 스키마는 해당 사용자나 응용 프로그램이 필요로 하는 데이터의 부분집합에 대한 뷰(View)로서 동작. 다수의 외부 스키마가 존재할 수 있음
개념 스키마전체 데이터베이스의 논리적 구조 정의. 모든 외부 스키마의 통합된 뷰로서, 데이터베이스의 전체적인 구조와 데이터 간의 관계를 나타냄. 데이터의 일관성과 무결성 유지 역할
내부 스키마데이터의 물리적 구조 정의. 데이터가 디스크에 저장되는 방식·인덱스 구조·저장 위치 등과 같은 물리적 세부 사항 정의. 성능 향상을 위해 최적화된 구조로 데이터를 관리
학교 데이터베이스를 생각하면 — 학생은 자신의 성적만 보는 화면을 사용하고(외부 스키마), 교무부는 전체 학생·수업·성적 구조를 관리하며(개념 스키마), 시스템은 실제 데이터가 디스크 어디에 저장되는지를 관리한다(내부 스키마).

② 데이터베이스 언어

데이터베이스를 정의하고 접근하기 위해 시스템과의 통신에 사용되는 언어. 데이터 정의어(DDL), 데이터 조작어(DML), 데이터 제어어(DCL)로 구분됨.

데이터 정의어(DDL, Data Definition Language)

  • 데이터베이스의 구조와 스키마를 정의하는 데 사용
  • 데이터베이스 객체(테이블·뷰·인덱스 등)의 생성·수정·삭제 담당

주요 명령어

명령어기능
CREATE테이블 생성
ALTER테이블 수정
DROP테이블 삭제

데이터 조작어(DML, Data Manipulation Language)

  • 데이터베이스에서 데이터를 조작하는 데 사용
  • 데이터의 검색·삽입·수정·삭제 등의 작업 수행

주요 명령어

명령어기능
SELECT데이터 조회
INSERT데이터 삽입
UPDATE데이터 수정
DELETE데이터 삭제

데이터 제어어(DCL, Data Control Language)

  • 데이터베이스의 보안·권한 관리·무결성 제약조건 등을 제어하는 데 사용
  • 데이터베이스에 접근하는 사용자나 응용 프로그램에 대한 권한을 부여하거나 제거

주요 명령어

명령어기능
GRANT접근 권한 부여
REVOKE접근 권한 회수
DDL·DML·DCL 구분 : DDL은 "테이블을 만들고 지우는" 구조 관련 명령, DML은 "데이터를 넣고 찾고 고치는" 데이터 관련 명령, DCL은 "누가 데이터를 볼 수 있는지 권한을 주고 빼는" 보안 관련 명령이다.

3) 키(Key)와 변수

① 키(Key)

데이터베이스에서 레코드를 고유하게 식별하는 역할을 하는 속성(열) 또는 속성들의 조합. 데이터의 고유성과 무결성을 보장하며, 데이터의 식별 및 검색에 사용됨.

키 종류내용예시
슈퍼키(Super Key)테이블 내에서 레코드를 고유하게 식별할 수 있는 속성 또는 속성들의 조합. 최소성 조건을 만족시키지 않을 수 있음책 테이블에서 "ISBN", "ISBN+책이름", "ISBN+책이름+저자" 모두 슈퍼키 가능
후보키(Candidate Key)슈퍼키의 특징을 가지면서도 최소성 조건을 만족하는 키. 기본키로 사용될 수 있는 집합책 테이블에서 "ISBN", "책이름+저자"
기본키(Primary Key)테이블에서 각 레코드를 고유하게 식별하기 위해 선택된 키. 중복된 값이 없어야 하고 NULL 값을 가질 수 없음 (NULL : 아무 값도 갖지 않는 경우. 0 또는 공백과 다름)책 테이블에서 "ISBN"을 기본키로 설정
대체키(Alternate Key)기본키가 될 수 있는 후보키 중 기본키로 사용되지 않는 키"ISBN"을 기본키로 설정했다면 "책이름+저자"는 대체키
외래키(Foreign Key)한 테이블에서 다른 테이블의 기본키를 참조하는 키. 테이블 간의 관계를 정의하고 참조 무결성을 유지주문 테이블의 "고객ID"가 고객 테이블의 "고객ID(기본키)"를 참조

② 변수

값을 저장하고 참조할 수 있는 메모리 공간. 데이터 처리 및 분석에 사용되며, 값을 저장하고 조작함으로써 원하는 결과를 얻을 수 있게 함.

독립변수와 종속변수

  • 독립변수(Independent Variable) : 종속변수에 영향을 주는 변수로, 원인이 되는 변수. 다른 변수들에 영향을 받지 않고 자유롭게 값을 변경할 수 있음
  • 종속변수(Dependent Variable) : 독립변수에 의해 영향을 받는 변수로, 결과 혹은 응답을 나타내는 변수. 다른 변수들의 변화에 따라 값이 변함
  • 예 : 제품 판매량을 예측한다면 판매량은 종속변수, 이에 영향을 미치는 광고 비용·가격을 독립변수로 사용

특성에 따른 변수 분류

변수내용예시
이산변수(Discrete Variable)정수 또는 유한한 값 중 하나를 가지는 변수. 개수나 빈도와 같은 계수적인 측면에서 분석주사위 눈의 개수, 가족 구성원 수
연속변수(Continuous Variable)실수 형태로 연속적인 값을 가지는 변수. 무한한 값을 가질 수 있음사람의 키, 몸무게, 온도
명목형 변수(Nominal Variable)범주를 표현하는 변수. 순서나 계층구조가 없음동물의 종류(개, 고양이, 새), 혈액형(A, B, AB, O)
순서형 변수(Ordinal Variable)범주를 순서대로 나타내는 변수. 상대적인 순서를 가짐학업 성적의 등급(A, B, C, D, F)
파생변수(Derived Variable)기존 변수를 이용하여 계산·변형·조합하여 생성된 변수키와 몸무게로부터 계산한 BMI
요약변수(Summary Variable)데이터의 특성을 요약하여 표현한 변수. 여러 개의 관측치를 대표하는 값으로 축약시험 점수로부터 계산한 평균·중앙값·최댓값
시계열 변수(Time Series Variable)시간에 따라 변화하는 값을 갖는 변수. 일정한 간격으로 측정되거나 관찰됨매일의 주가, 매월의 판매량, 연간 기후 데이터

4) 분산 데이터베이스

① 분산 데이터베이스 개념

물리적으로 분산된 데이터베이스 시스템을 네트워크로 연결해 사용자가 논리적으로는 하나의 중앙 집중식 데이터베이스 시스템처럼 사용할 수 있도록 한 것.

전국에 지점이 있는 은행을 생각하면 쉽다. 실제 데이터는 서울·부산·광주 등 각 지역 서버에 나뉘어 저장되어 있지만, 고객은 어느 지점에서든 하나의 은행 시스템처럼 사용할 수 있다. 이것이 분산 데이터베이스다.

② 분산 데이터베이스 시스템의 주요 구성 요소

구성 요소내용
분산 처리기(Distributed Processor)지역별로 필요한 데이터를 처리할 수 있는 지역 컴퓨터. 각 지역의 데이터베이스를 자체적으로 관리하는 DBMS를 별도로 가짐
분산 데이터베이스(Distributed Database)물리적으로 분산된 지역 데이터베이스로, 해당 지역에서 가장 많이 사용하는 데이터를 저장
통신 네트워크분산 처리기는 통신 네트워크를 통해 자원을 공유하며 특정 통신 규약에 따라 데이터를 전송

③ 분산 데이터베이스 시스템의 장단점

구분내용
장점신뢰성·가용성 증대 (장애 발생 시 다른 지역 DB 이용 가능) / 지역 자치성·효율성 증대 (응답 시간 단축, 통신 비용 절약) / 확장성 증대 (새로운 지역에 DB 설치로 용량 확장 가능)
단점설계 및 구축 비용이 많이 발생 / 여러 지역에 대한 관리가 복잡함 / 오류의 잠재성 증대 / 데이터 무결성에 대한 위협 증대 / 불규칙한 응답속도

④ 분산 데이터베이스 시스템의 투명성 유형

투명성내용
분할 투명성하나의 논리적 관계가 여러 단편으로 분할되어 각 단편의 사본이 여러 사이트에 저장됨
위치 투명성사용하는 데이터의 저장 장소를 명시할 필요 없음. 위치 정보는 시스템 카탈로그에 유지됨
지역사상 투명성지역 DBMS와 물리적 DB 사이에 연계(Mapping)를 보장함
중복 투명성DB 객체가 여러 사이트에 중복되어 있는지 알 필요가 없음
장애 투명성구성요소의 장애에 무관한 트랜잭션의 원자성 유지
병행 투명성다수의 트랜잭션을 동시에 수행해도 트랜잭션의 결과는 영향을 받지 않음
사용자가 데이터가 서울 서버에 있는지 부산 서버에 있는지 몰라도 조회할 수 있다면 위치 투명성, 같은 데이터가 여러 서버에 복사되어 있어도 사용자가 이를 의식하지 않아도 된다면 중복 투명성에 가깝다.
