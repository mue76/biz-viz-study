① 파일시스템 vs DBMS
파일시스템
장점
단순, 직관적
단점
데이터 중복, 검색 제한, 동시 접근 어려움
종류
FAT32, NTFS, APFS (타 OS 호환 어려움) 등
DBMS
등장 배경
파일시스템 단점을 극복하기 위해
특징
중복 최소화, 무결성, 동시 접근 제어, 보안
RDBMS
테이블 구조, SQL, 정형 데이터 최적화
NoSQL
유연한(동적) 스키마, 비정형·반정형 처리
※ 계층형 구조 저장은 RDBMS의 특징이 아님
② 데이터베이스 구성요소
구성요소설명

속성 (Attribute)테이블의 열 (= 필드, 변수)
레코드 (Record)테이블의 행 (= 튜플)
메타데이터데이터에 대한 데이터 (구조, 제약조건 설명)
데이터 딕셔너리스키마와 메타데이터를 저장·관리
트랜잭션 관리자일관성·동시성 제어 담당
저장 데이터 관리자물리적 저장·배치 담당
③ 키(Key) 종류
키 종류설명
슈퍼키유일성만 만족 (최소성 불필요)
후보키유일성 + 최소성 모두 만족
기본키후보키 중 선택, NULL 불가·중복 불가
대체키후보키 중 기본키로 선택되지 않은 것
외래키다른 테이블의 기본키 참조 (테이블 간 관계)
④ 스키마 3단계
외부 스키마
사용자·앱 관점의 뷰 (다수 존재 가능)

내부 스키마
물리적 저장 구조 (디스크 저장 방식)
※ 3단계 스키마는 사용자 관점, 논리 구조, 물리 저장 구조를 구분하는 개념
